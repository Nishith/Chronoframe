## Tie-break rule for new gaps
When a gap appears that no contract or decision covers, choose the option that, in this order: (1) keeps every `AGENTS.md` safety invariant; (2) changes wording or layout only, never engine behavior; (3) changes the fewest existing files and lines; (4) copies an existing pattern from the reference file the WP names; (5) uses the C-01 glossary for any new user-visible word. Log it as `D-CLP-1NN` with the WP ID, the options and the choice. Never use the tie-break to weaken a safety rule; log that in `BLOCKED.md` instead.

## Scope and process
- **D-CLP-05 Plan location.** `docs/plan/clear-path/`. Shared rules: `docs/plan/next-half/AGENT_RULES.md`. The rationale is `CONTRACTS.md` "Findings", not the product review the shared kickoff names.
- **D-CLP-06 Status of the design.** All eight review proposals are **approved** (owner, 2026-11-12). Exact copy in the contracts is **proposal** until the owner reads it in the running app (row H-CLP-6); agents implement it exactly anyway.
- **D-CLP-07 Identifiers never change.** Every existing accessibility identifier keeps its value, including `transferButton`, `startTransferFromPreviewButton` and `organizeTab.<rawValue>`. Where a control is removed, its identifier constant stays in `AccessibilityIdentifiers` (unused) so the list at `:168` and its tests keep compiling; where a control moves, the identifier moves with it.
- **D-CLP-08 "Receipt" stays.** The word is product vocabulary in docs, History and `AGENTS.md`. On first-contact surfaces it is always explained in the same sentence ("a receipt you can undo from History"). No rename.
- **D-CLP-09 "Destination" stays; "source" goes.** "Destination" reads plainly. "Source" becomes "folders to organize" (noun phrase) or "originals" (the files). `Unknown_Date` and `Duplicate` stay verbatim because they are real folder names the user will see in Finder.
- **D-CLP-10 Setup no longer starts a copy.** The Transfer button leaves Setup and the toolbar. A copy starts from the Preview-ready hero, or from the Organize menu command (kept for experienced users, renamed "Start Copying"). The engine's own confirmation prompt is unchanged in behavior.
- **D-CLP-11 Toolbar shows Stop only.** `RootSplitView`'s Preview and Transfer toolbar buttons are removed; the hero carries the one action. The Cancel toolbar button stays while a run is in progress, labeled "Stop".
- **D-CLP-12 Layout picker is the same preference.** The Setup picker binds to `PreferencesStore.folderStructure`, the value Settings › Layout already edits. No second source of truth. The Reorganize action stays in Settings.
- **D-CLP-13 Example tree comes from the real path builder.** `FolderLayoutPresentation.exampleLines` calls `PlanningPathBuilder.buildDestinationPath`; a hand-written example would drift.
- **D-CLP-14 Headline counts come from existing models.** `RunMetrics` and `PreviewReviewSummary` only. No new engine output, no folder count (the engine does not report one); the date span comes from `RunMetrics.dateHistogram` keys and is omitted when they do not parse.
- **D-CLP-15 Hand-off navigates, nothing more.** "Find Duplicates" opens the Deduplicate workspace. It does not change the user's chosen scan folder and does not start a scan.
- **D-CLP-16 Dedupe lanes are a view over the store.** `DeduplicateSessionStore`, `DeduplicationPlanner`, `DeduplicateExecutor` and `DeduplicateModels` decision logic are not edited. The lanes call `acceptAllSuggestions()` and open the existing Quick Review sheet. The only Core edit in dedupe is `ClusterKind.title` for `.nearDuplicate`.
- **D-CLP-17 "Safe" wording must match the gate.** A group is called safe only if `DeduplicationPlanner.isAutomaticCommitEligible` returns true for it. The lane sentence says "safe matches", not "exact copies", unless the reviewer confirms the gate admits exact duplicates only.
- **D-CLP-18 Multi-folder list persists through bookmarks.** Keys `manual.sourceItem.<index>`; paths in `PreferencesStore.manualSourceItemPaths`. The staging directory is rebuilt at launch because `SetupCoordinator.bootstrap` wipes it. A folder whose bookmark no longer resolves is dropped from the list silently at launch and its key removed (same policy as `BookmarkPathResolver.resolveBookmarkedPath`).
- **D-CLP-19 Nested folders.** Adding a folder that is inside a listed folder is refused with a plain message. Adding a folder that contains listed folders replaces them. Adding the same folder twice is a no-op.
- **D-CLP-20 INV-21 for staged sources is closed in the engine, test first.** Today the overlap guard compares the staging directory, not the manifest's items, with the destination (`SwiftOrganizerEngine.swift:472`). WP-02 writes the failing test first. If it already passes (discovery rejects the overlap), WP-02 is test-only and says so. Setup also refuses the overlap when a folder or destination is chosen, but the engine check is the gate.
- **D-CLP-21 Profiles stay single-folder.** Saving a profile while two or more folders are listed is refused with a plain message. Selecting a profile hides the manual list without deleting it; clearing the profile brings it back.
- **D-CLP-22 Health score needs history.** The dial and "Library shape" bar are hidden until the destination has at least one receipt. Zero receipts is `.good`, not `.attention`.
- **D-CLP-23 No new invariant.** Tests are tagged `// AGENTS-INVARIANT: 21` (multi-item overlap), `1` (list never writes to a listed folder: staging lives in Caches) and `6` (lane never calls a non-eligible group safe).
- **D-CLP-24 Test placement.** Core and AppCore tests in `ui/Tests/ChronoframeAppCoreTests/`; App tests in `ui/Tests/ChronoframeAppTests/`. XCUITest and `A11yBaseline.json` edits are orchestrator-only (WP-13). `project.pbxproj` is never edited.
- **D-CLP-25 Strings.** New and changed literals are Swift literals; the orchestrator adds English keys at G2 in each catalog's existing JSON style (see `docs/plan/photos-import-resume/DECISIONS.md` D-PIR-120: the shared script re-serializes, so use the inline style-preserving approach). Old keys are left in the catalogs; removing them is an owner step with translations.
- **D-CLP-26 Existing tests that pin old wording are updated, not deleted.** A test that asserts a renamed string changes its expected value to the C-01/C-0x text in the same WP. No test is skipped or removed. The owned-paths line of each WP names the test files.
- **D-CLP-27 Meridian rules hold.** No new gradients, no nested cards, native controls, motion through `Motion`, text sized with `.scaledFont`. New explanatory sentences are allowed only where a contract gives them.
