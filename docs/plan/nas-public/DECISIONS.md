## Runtime decisions
- **D-NASP-101 Scan refusal placement (WP-01).** In `NativeDeduplicateEngine.scan` the refusal sits after the existing `activeLease?.release()` and immediately before `DestinationOperationLock.acquire`. C-02 says "after the guard, before acquire"; releasing a prior lease writes nothing, and checking earlier would keep a stale lease across a refused scan.
- **D-NASP-102 AppState message tests pin the flag (WP-01).** The three AppState refusal tests set `NASCapability.isEnabledOverride = false` (DEBUG only, restored with `defer`) so `transientErrorMessage` is compared to the exact C-01 flag-off text. The history-shortcut refusal shows the C-01 text, not the "no longer available" copy.
- **D-NASP-103 Harness classifier default is local (WP-01).** `AppStateHarness.makeAppState` defaults `volumeClassifier:` to `AppStateHarness.localClassifier` (apfs, `MNT_LOCAL`) so existing `/Volumes/...` fixture paths are not refused; `AppStateHarness.remoteClassifier` (smbfs) is opt-in. Both are `nonisolated static let`.
- **D-NASP-104 WP-02 grep form.** The `execute` signature is multi-line, so the plan's literal grep `public func execute(queuedJobs` never matches. Equivalent checks used: `grep -n "public func execute($"` prints nothing; `grep -n "func execute($"` prints one line (447).
- **D-NASP-105 Keeper status placement (WP-03).** The keeper controls live in `NASExactGroupDetailView.swift` (not owned), so the one-line status sits in `NASLibraryView.swift` directly below the group list/detail row, extracted as internal `NASKeeperSaveStatusView` so it can be render-tested over an injected store (`NASLibraryView` only builds from `AppState`). Departs from C-05 "add the `Text` only" by one internal wrapper struct; no public API.
- **D-NASP-106 Keeper copy lives twice (WP-03).** AppCore can't see `NASLibraryCopy`, so the store uses an internal literal `NASWorkspaceStore.keeperSaveFailedMessage` and the view renders it via `Text(LocalizedStringKey(message), bundle: .module)` with `NASLibraryCopy.keeperSaveFailed` carrying the same words; a test asserts equality. The sentence goes in `strings-app.txt`, not `strings-core.txt`.
- **D-NASP-107 Validate timeout not injectable (WP-03).** The store uses `NASReconnectProbe.observeWithTimeout` with the 2.0 s default (no new init parameter); `ProbeGate` became generic but stays private.
- **D-NASP-108 Keeper message reset scope (WP-03, review round 1).** Beyond C-05's "clear on next successful `chooseKeeper`", `keeperSaveMessage` is also cleared in `loadSavedLibrary`, `validate`, the library-change branch of `chooseLibrary`, `apply`, and `startAssessment`, so a failed save never shows under another library's results. Test `testKeeperSaveMessageClearsWhenLibraryChanges`.
- **D-NASP-109 No accessibility identifier on the keeper status (WP-03).** `AccessibilityIdentifiers` is outside owned paths; follow-up if UI tests need it.
- **D-NASP-110 String lists by content (WP-04).** C-09 line ranges were stale after WP-03, so literals were located by content. Interpolated literals (`"\(folders) folders"`, `"\(media) photos and videos"`, `"\(groups) groups of identical files"`, `"\(count) identical copies of \(name), \(size) each"`, `"Keeper chosen: \(…)"`) are skipped because `add_xcstrings_keys.py` has no format-key handling and they are never catalog lookups. `%@ in identical extra copies (logical size, not space freed)` is included (looked up via `String.LocalizationValue`). "Folder summary" listed once. `controlLabels` are listed per C-09 although `.accessibilityLabel(String)` may not localize them.
- **D-NASP-111 FAQ entry replaced (WP-04).** The old FAQ "Can Chronoframe remove duplicates on my NAS?" said Deduplicate shows only a one-time warning, which WP-01 made false; it is replaced by C-08's "Can I deduplicate a folder on my NAS?" quoting both C-01 variants.
