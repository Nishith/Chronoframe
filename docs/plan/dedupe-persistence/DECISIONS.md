# Dedupe persistence — decisions

Prefix `DDP`. Runtime decisions appended as `D-DDP-1NN`.

## Tie-break rule for new gaps
Keep every invariant (INV-06, 12, 14, 17, 18, 20 and the new INV-29 above all); fewest changed lines; copy the named reference pattern; fail closed (drop a saved choice rather than apply it). Log as `D-DDP-1NN`; safety weakening goes to `BLOCKED.md`.

- **D-DDP-01 Branch.** `feature/dedupe-persistence` stacked on `feature/nas-v1` at `4079fb1` (owner decision 2026-11-11: nas-v1 is unmerged and `main` lacks `docs/plan/` and INV-28). Rebase or merge after nas-v1 lands. Guards use base ref `feature/nas-v1`. Never push.
- **D-DDP-02 Identity, not path, is the key.** A saved choice is restored only when `scanSnapshot.identitiesByPath[path] == saved.identity`. Group approvals are keyed by sorted member identities because cluster UUIDs are regenerated each scan.
- **D-DDP-03 Decisions restore regardless of settings; the banner says when settings changed.** Content-identical files keep their Keep/Delete choice under any threshold. Approvals are protected by member identity, so a different threshold that regroups files simply yields unmatched (changed) groups.
- **D-DDP-04 Changed content clears the choice and un-approves the group.** No "stale Delete" can survive: a changed member drops its decision, and C-02 rule 4 withholds approval for its group.
- **D-DDP-05 Storage location.** Application Support `dedupe_reviews/<folderKey>.json`, one file per dedupe root. Not in the root's `.organize_cache.db`: the root may be read-only to us during review, and `ReviewOverrides` semantics (Organize) differ.
- **D-DDP-06 Lifecycle.** Saved on every change (debounced), on pause, cancel, reset and app termination. Removed on successful commit for that folder and on explicit Discard. Changing folder never removes it.
- **D-DDP-07 Saving is best-effort and silent.** A failed save (disk full, permissions) is not surfaced during review; the next relaunch simply has an older snapshot. Reviewer checks that no user-facing error is invented for this path.
- **D-DDP-08 Focus is the cluster key.** `reviewFocusClusterID` is set by the view; captured as the group key; restored to the matching cluster if any.
- **D-DDP-09 No undo for the restore itself.** Restoring happens before the user acts; registering it would make the first ⌘Z discard the whole restore. The user can "Discard Saved Review" from the idle card or change choices normally.
- **D-DDP-10 `pairKeepOverrides` and `hardDelete` are not persisted.** The UI never writes overrides; `hardDelete` is forced false by `DedupeDecisions.init`.
- **D-DDP-11 Test placement.** Core tests `ui/Tests/ChronoframeAppCoreTests/ChronoframeCoreDeduplicateReview*Tests.swift`; store tests in a new `DeduplicateReviewPersistenceTests.swift` alongside `DeduplicateSessionStoreTests.swift`; App tests `ui/Tests/ChronoframeAppTests/DeduplicateReview*Tests.swift`.
- **D-DDP-12 New invariant INV-29** added at G1 by the orchestrator with the exact C-07 text.

## Runtime decisions
- **D-DDP-101 Approval needs every member's own saved choice restored (orchestrator, WP-01).** `FileIdentity` is content-only, so a group key does not bind paths. A cluster is restored as approved only when key and member count match **and** every member path had a saved decision restored. Stricter than C-02 rule 4; fail closed. Covers renamed/moved members and two clusters with the same identity multiset.
- **D-DDP-102 Empty cluster has no group key** (`groupKey(for:snapshot:)` returns nil).
- **D-DDP-103 Fingerprint text.** Every `DeduplicateConfiguration` field except `workerCount` in declaration order, `destinationPath` included, `videoPerceptualMatchConfiguration` flattened; `additionalSources` entries joined by U+001E, their fields by U+001F; SHA-256 lowercase hex. A format change only flips `settingsChanged`.
- **D-DDP-104 `capture` output.** `folderPath` standardized; decisions sorted by path; every decision with a scan identity is kept (not only cluster members); approvals in cluster order; focus nil when the focus cluster has no key.
- **D-DDP-105 Counts.** `restoredGroupCount = approvedClusterIDs.count`; `changedGroupCount = max(0, approvals.count − restoredGroupCount)`; focus mapping is independent of approval.
- **D-DDP-106 "Member of some cluster" means `members[].path`.** The session store only keys decisions by member path; paired and sidecar paths never appear in `byPath`.
- **D-DDP-107 Only a touched review is saved (orchestrator, WP-02).** `saveNow()` writes only after a user action or an applied restore (`reviewHasUserChanges`). Untouched suggestions never create a saved review, so no card or banner appears for work the user did not do. Consequence: after a restore, the next save overwrites the file with current state, so choices dropped because a file changed are gone from disk too (fail closed).
- **D-DDP-108 `startScan` flushes a pending save first**, under the previous scan's folder, before any state is cleared.
- **D-DDP-109 XCTest default directory.** `DeduplicateReviewFileSnapshotStore.defaultDirectory()` returns a fresh temp directory per call when `XCTestCase` is loaded (same guard as `SpotlightIndexer`), so default-constructed stores in existing tests never touch real Application Support. Those temp directories are not cleaned up.
- **D-DDP-110 Commit removal applies to forward commits only**; a revert never removes a saved review. `cancel()` and `pauseReview()` save only when the review guard passes (a cancel during scanning writes nothing).
- **D-DDP-111 Extra tests beyond the plan's list:** `testCancelSavesImmediately`, `testUntouchedReviewIsNotSaved`, `testRestoredReviewIsSavedAgainOnPause`, `testStartScanFlushesPendingSave`, and three D-DDP-101 restorer tests.
- **D-DDP-112 Singular wording (orchestrator, WP-03).** A count of exactly 1 uses singular copy through explicit keys: count phrases (`1 choice` / `%lld choices`, `1 group` / `%lld groups`, `1 reviewed group` / `%lld reviewed groups`) composed into `%@ across %@ from %@.` and the saved-body sentence; separate singular sentences for the changed-group and cleared-file clauses. Replaces C-05's plural-only strings; 18 keys in `strings-app.txt`.
- **D-DDP-113 Banner dismissal is view-local state** keyed on `restoredReview.savedAt`; no store API added. It can reappear if the view is rebuilt mid-review.
- **D-DDP-114 Saved-review card refresh and gating.** Refreshed on appear, on dedupe-folder change and whenever status returns to idle; shown only with a non-empty dedupe path, a saved review and no paused review. Any scan of the folder restores, not only the card's button.
- **D-DDP-115 Body copy is localized** through `Bundle.module` format keys; `restoredBody`/`savedBody` take `locale:`/`timeZone:` (default `.current`); date style is abbreviated month, day, hour, minute. Added accessibility label `Dismiss` for the banner's close button.
- **D-DDP-116 Termination observer** uses `queue: nil` so the flush runs synchronously on the posting (main) thread; no removal in `deinit` (`AppState` lives for the app's lifetime).
- **D-DDP-117 String catalog formatting.** `add_xcstrings_keys.py` re-serializes the catalog with `"key": value` separators, while the committed catalog uses Xcode's `"key" : value`. For this plan the orchestrator re-wrote the result in the existing style and order so the diff is the 18 new keys only. The script itself is unchanged (shared file); fix it before the next plan uses it.
- **D-DDP-118 G2 app smoke not run.** Owner chose "try via computer use" up front, then declined the access prompt at G2. No retry. The two smoke screenshots are owner work alongside H-DDP-1/2.
- **Open for owner (not a decision):** the card and banner counts include untouched suggestions for every file in a group once a review is touched (capture records a choice per member, which D-DDP-101 needs). "N choices" can therefore be much larger than the number of changes the user made. Counting only user-made choices needs a snapshot field marking them; not done. **Resolved by D-DDP-119.**
- **D-DDP-119 Counts cover reviewed groups only (owner, 2026-11-12: fix before merge).** Each saved decision records `inReviewedGroup` (its path belonged to a group marked reviewed when the save was captured). Every store action that changes a choice also marks its group reviewed, so this is exactly the set of choices the user made or confirmed. The card and banner count only those; cleared-choice counts likewise. Every decision is still saved and restored, and the approval rules (INV-29, D-DDP-101) are unchanged. A saved file without the field decodes as `true` (old behaviour). WP-05, C-10.
- **D-DDP-120 Folder key is a SHA-256 of the path (PR #267 review, 2026-11-13).** The base64url of the whole path became the filename, so a dedupe folder path of about 190 characters or more exceeded the 255-character filename limit and every save failed silently. The key is now 64 hex characters. No saved review has shipped, so there is no migration; a review saved by an earlier local build of this branch is not found again. Failing-first not applicable to the length test before the change in the same commit; `testFolderKeyStaysWithinTheFilenameLimitForDeepFolders` pins it.
- **D-DDP-121 A commit flushes the pending save first (PR #267 review, 2026-11-13).** `commitReviewed` changed the status before the debounced save ran, and the save guard refuses anything but an open or paused review, so choices made within the debounce window were lost when the commit failed. It now calls `flushPendingReviewSave()` first. Failing-first: `testCommitFlushesPendingSave` (0 saves before the fix). A successful commit still removes the saved review.
- **D-DDP-122 A restore that restored nothing is not a touched review (PR #267 review, 2026-11-13).** Restore set `reviewHasUserChanges = true` unconditionally, so after a rescan that dropped every saved choice and approval, a reset, pause or cancel overwrote the saved review with untouched suggestions. The flag now follows the restore only when it restored at least one reviewed decision or approval. Upholds D-DDP-107. Failing-first: `testNothingRestoredLeavesSavedReviewUntouchedOnReset` (1 save before the fix, 0 after).
- **D-DDP-123 An untouched review is an empty snapshot (PR #267 review, 2026-11-13).** `capture` records a decision for every member (D-DDP-104), so `isEmpty` was never true and the file store's "empty snapshot removes the file" path was dead (for example after the user undid everything back to suggestions). `isEmpty` is now "no approvals and no decision with `inReviewedGroup`". `capture` is unchanged; a file from an earlier build without the field decodes as reviewed and stays non-empty. Failing-first: `testCaptureOfAnUntouchedReviewIsEmpty`, `testSnapshotOfOnlyUnreviewedDecisionsIsEmpty`.
- **D-DDP-124 Unreviewed decisions restore only into an intact cluster (PR #267 review, 2026-11-13).** A saved decision from a never-approved group records no cluster, and restore overlaid it by path, so a cluster that gained or lost members could inherit part of the old arrangement and end with no keeper (saved {A: Delete, B: Keep}, new cluster {A, D} with suggestion A Keep / D Delete became A Delete, D Delete). Decisions with `inReviewedGroup == false` now restore for a cluster only when every member has a matching saved decision (identity and path) and the overlaid cluster still has a Keep; otherwise the cluster keeps its fresh suggestion. Reviewed-group decisions are unchanged (D-DDP-03, D-DDP-101). `DeduplicationPlanner` already skips an all-Delete cluster (never empties a cluster), so this was a wrong-suggestion bug, not a data-loss path. Failing-first: `testUnreviewedDecisionIsNotRestoredIntoAChangedCluster`, `testUnreviewedDecisionsThatWouldLeaveNoKeeperAreNotRestored`.
- **D-DDP-125 Approvals carry across a settings change (PR #267 review, 2026-11-13; no code change).** Reaffirms D-DDP-03: restore is gated by member identity and group key, not by the configuration fingerprint; `settingsChanged` only drives the banner. A threshold change that regroups files yields unmatched groups (counted as changed), and a group whose members are all identical still keeps its approval.
- **D-DDP-126 The store publishes the saved-review card (PR #267 review, 2026-11-13).** The view refreshed the card only when status changed to `.idle`, so `reset()` on an already-idle paused review saved without refreshing. `refreshSavedReview(folderPath:)` now records the folder the view shows, and every `saveNow()` for that folder (standardized) re-reads it into `savedReviewForCurrentFolder`; saves for another folder leave the card alone. The view's `.idle` refresh is removed; appear and folder-change refreshes stay (amends D-DDP-114). Failing-first: `testSavingRefreshesTheSavedReviewCardWithoutAViewCall`.
